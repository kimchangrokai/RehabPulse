# PRD — 회사·프로젝트·수신자별 사건 감시 (RehabPulse)

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 |
| 작성일 | 2026-09-01 |
| 상위 문서 | [PRD.md](PRD.md) — 조회·인가 판정·결번·캡차 규칙은 그쪽이 우선 |
| 제품 | RehabPulse |
| 상태 | 구현됨 (PR #9, 보고서 재조회 제거는 PR #10) |

> 이 문서는 **업체(회사) → 프로젝트 → 사건 / 수신자** 분류만 다룬다. 나의 사건검색 파싱, 인가 판정, 3일 결번 종료는 상위 PRD를 따른다. 이 문서와 상위 PRD가 충돌하면 **분류·메일 수신자·스케줄 범위는 이 문서**, 포털 조회 규칙은 상위 PRD가 우선한다.

---

## 1. 배경 및 문제 정의

v1 RehabPulse는 **전역 사건 목록 하나**와 **수신자 하나**(`settings.yaml`의 `email.recipients`)로 동작했다. 조회·변경 메일이 모든 관심 사건에 대해 같은 주소로 나갔다.

실무에서는 다음이 필요하다.

1. 의뢰 **회사**가 여럿이다 (예: 대신증권, 삼성증권).
2. 회사마다 **계약 프로젝트**가 따로 있다 (예: `2608계약건` = 2026년 8월 계약).
3. 프로젝트마다 **담당자**가 여러 명일 수 있고, **메일 수신자**는 담당자와 다를 수 있다.
4. 사건 목록과 메일링 리스트를 회사·프로젝트 단위로 분리해야 한다.
5. 비전 캡차로 사건 수가 수백 건이 되면 한 프로세스 순차 조회로는 메일 시각을 맞추기 어렵다. 프로젝트는 **독립 프로세스로 병렬**이어야 한다.

## 2. 목표

| 목표 | 성공 지표 |
|---|---|
| 회사·프로젝트 단위로 사건 목록을 분리 | 프로젝트마다 엑셀 워크북 하나. 회사는 폴더 |
| 프로젝트마다 담당자와 메일링을 따로 관리 | 담당자 시트와 메일링리스트 시트가 별개. 변경·보고서 메일은 메일링만 |
| 조회/보고 범위를 실수로 전건 치지 않음 | `sync`/`report`/`mail`에 `--company` 또는 `--project` 필수 |
| 프로젝트별 조회·메일 시각 | sidecar YAML의 `lookup_time` / `mail_time`. 기본 04:00 / 07:00 |
| 병렬 조회 | 회사의 여러 프로젝트는 서로 다른 OS 프로세스. 브라우저·캡차 클라이언트 비공유 |
| 운영 실패 가시성 | 재시도 후 남은 이상(보고서 없음, SMTP 실패, 조회 error, 결번)은 관리자 메일 |

### 비목표

- 회사 단위 공통 메일링 리스트
- 전역 단일 `rehabpulse.xlsx`
- 한 프로세스에서 전 프로젝트 순차 조회
- 다중 사용자 로그인 / SaaS / 권한 모델
- 포털 조회 규칙(캡차, 하루 2회, 3일 결번) 변경
- 기존 v1 시드 6건 자동 이전

## 3. 계층과 용어

```
회사 (폴더)
 └── 프로젝트 (xlsx + yaml)
      ├── 사건목록 · 일반내용 · 진행명령 · …
      ├── 담당자 (이름 + 이메일)     ← 명단. 메일을 자동 수신하지 않음
      └── 메일링리스트 (이메일)      ← 변경 알림 · 현황 보고서 수신자
```

| 용어 | 의미 |
|---|---|
| 회사 | 의뢰 업체. 디렉터리 이름. 예: `대신증권`, `삼성증권` |
| 프로젝트 | 회사의 계약 단위. 파일 이름. 예: `2608계약건` (YYMM + `계약건`) |
| 담당자 | 프로젝트 실무 명단. 이름+이메일, 0명 이상 |
| 메일링 리스트 | 알림을 받을 이메일. 담당자와 독립 |
| 관리자 | 운영 실패 알림만 받음. 사건 변경 메일은 받지 않음 |

## 4. 저장

### 4.1 경로

| 종류 | 경로 |
|---|---|
| 워크북 | `data/{회사}/{프로젝트}.xlsx` |
| 스케줄 | `data/{회사}/{프로젝트}.yaml` |
| 당일 보고서 | `reports/{회사}/{프로젝트}/{YYYY-MM-DD}.md` |
| 백업 | `backup/{회사}/{프로젝트}/` |

전역 `rehabpulse.xlsx`는 쓰지 않는다.

### 4.2 워크북 시트

기존: `사건목록`, `일반내용`, `진행명령`, `변경이력`, `실행로그`, `종료목록`

추가:

| 시트 | 열 | 규칙 |
|---|---|---|
| `담당자` | 이름, 이메일 | 같은 이메일 중복 등록 거절 |
| `메일링리스트` | 이메일 | 같은 이메일 중복 등록 거절 |

### 4.3 사건 키

- 한 워크북 안: **법원 + 사건번호** 유일. 중복 `add`는 거절.
- 다른 프로젝트: 같은 법원+사건번호 **허용** (두 회사가 같은 사건을 각자 감시).

### 4.4 sidecar YAML

```yaml
lookup_time: "04:00"
mail_time: "07:00"
```

프로젝트마다 시각을 바꿀 수 있다. 새 프로젝트 기본값은 위와 같다.

## 5. 수신자 규칙

| 메일 종류 | 수신자 |
|---|---|
| 사건 변경 알림 (`PLAN_APPROVED` 등) | 그 프로젝트 `메일링리스트`만 |
| 현황 보고서 (`mail` / `report --email`) | 그 프로젝트 `메일링리스트`만 |
| 점검 실패 (보고서 없음, SMTP 실패, 조회 error, 결번 miss) | 관리자 `realtyscope.ai@gmail.com`만 |

- 담당자 이메일은 메일링에 자동으로 넣지 않는다.
- 회사 공통 수신자 목록은 없다.
- SMTP 발신: `realtyscope.ai@gmail.com` (`config/settings.yaml` `email.sender`).
- 워크북 첨부: `email.attach_workbook` (기본 `false`). true이면 해당 프로젝트 xlsx를 첨부.
- 비밀번호: 환경변수 `REHABPULSE_SMTP_PASSWORD` (없으면 `AUCTIONPULSE_SMTP_PASSWORD`).

## 6. 조회·메일 시각과 병렬

| 시각 | 작업 | 포털 |
|---|---|---|
| `lookup_time` (기본 04:00) | `sync` — 조회, 엑셀 저장, **당일 보고서 파일 생성**. 메일 없음 | 침 |
| `mail_time` (기본 07:00) | `mail` — 보고서 파일 발송 + 당일 변경 알림 + 점검 | **치지 않음**. 보고서 파일이 없으면 엑셀에서만 재생성 |

- 평일(월–금)만 실행. 주말은 조회·메일·관리자 알림을 건너뛴다.
- `--company`만 주면 그 회사의 프로젝트마다 **별도 프로세스**로 실행한다.
- 프로젝트 간 브라우저·캡차 클라이언트를 공유하지 않는다.
- Windows 작업: 프로젝트마다 Lookup 작업 + Mail 작업 (`scripts/register_task.ps1`).

SMTP 실패 시 추가 재시도 2회. 그래도 실패·error·결번이면 관리자 메일.

## 7. CLI

스코프: `sync` / `report` / `mail` / `add` / `remove` / `list` 는 `--company` 필요. `--project`만 있으면 오류. `--company`만 있으면 그 회사 전체 프로젝트.

```
python -m rehabpulse init
python -m rehabpulse add "인천지방법원 2024개회176313" --party "박미리" --company 대신증권 --project 2608계약건
python -m rehabpulse list --company 대신증권 --project 2608계약건
python -m rehabpulse sync --company 대신증권 --project 2608계약건
python -m rehabpulse report --company 대신증권 --project 2608계약건
python -m rehabpulse mail --company 대신증권 --project 2608계약건
```

- `init`: TEST 회사·프로젝트 생성 (아래 초기 데이터).
- 인자 없는 `sync`/`report`/`mail`은 오류로 종료하고 포털을 치지 않는다.

## 9. 기능 요구사항

### FR-C. 회사·프로젝트 저장소

- FR-C.1 회사는 `data/{회사}/` 디렉터리다.
- FR-C.2 프로젝트는 `{프로젝트}.xlsx` + `{프로젝트}.yaml` 쌍이다.
- FR-C.3 `init`은 §8의 두 회사·프로젝트를 만들고 메일링 두 주소를 넣는다.

### FR-P. 사건 목록

- FR-P.1 사건은 프로젝트 워크북의 `사건목록`에만 속한다.
- FR-P.2 같은 워크북에서 법원+사건번호 중복 등록은 거절한다.
- FR-P.3 다른 프로젝트에는 같은 사건을 등록할 수 있다.

### FR-R. 담당자·수신자

- FR-R.1 담당자: 이름+이메일, 복수, 메일 자동 수신 없음.
- FR-R.2 메일링 리스트: 이메일만, 복수.
- FR-R.3 변경 알림과 현황 보고서는 메일링 리스트만 받는다.
- FR-R.4 관리자 메일은 `realtyscope.ai@gmail.com`만 받는다. 사건 변경을 받지 않는다.

### FR-S. 스코프·스케줄

- FR-S.1 `sync`/`report`/`mail`은 `--company` 또는 (`--company`와 `--project`)가 필요하다.
- FR-S.2 `--company`만 있으면 프로젝트별 독립 프로세스로 실행한다.
- FR-S.3 조회 시각과 메일 시각은 YAML에서 분리한다. 기본 04:00 / 07:00.
- FR-S.4 `sync`는 조회 후 당일 보고서 파일을 남기고 메일을 보내지 않는다.
- FR-S.5 `mail`은 그 파일을 보낸다. 파일이 없으면 엑셀에서만 보고서를 만들고 포털을 다시 치지 않는다.
- FR-S.6 평일만 동작한다.

## 11. 결정된 것

- 저장: 프로젝트마다 xlsx 하나. 경로 `data/{회사}/{프로젝트}.xlsx`.
- 스케줄: sidecar YAML. 조회 04:00 / 메일 07:00 분리.
- 메일링과 담당자 분리. 회사 공통 메일링 없음.
- 변경·보고서는 프로젝트 메일링만. 관리자는 실패만.
- 사건 유일 범위는 워크북. 프로젝트 간 중복 허용.
- CLI는 회사 또는 회사+프로젝트 지정 필수. 프로젝트만은 불가.
- 병렬: 프로젝트별 OS 프로세스.
- 평일만. 주말 관리자 알림 없음.
- `sync`가 당일 보고서를 남긴다. `mail`은 재조회하지 않는다.
