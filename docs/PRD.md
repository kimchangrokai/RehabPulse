## 1. 배경 및 문제 정의

개인회생 사건의 **변제계획인가결정**은 이후 변제·면책 실무의 분기점이다. 관심 사건(수임 사건 등)의 인가 여부를 알려면 대법원 나의 사건검색에 사건마다 접속해 일반내용·진행내용을 눈으로 확인해야 한다.

현재 병목:

1. 사건마다 법원 / 년도 / 사건구분 / 일련번호 / 당사자명 / 캡차를 다시 넣는다.
2. 인가 여부는 `변제계획인가일`이 채워졌는지, 진행내용의 명령 목록에 `변제계획인가결정`이 생겼는지를 사람이 기억에 의존해 비교한다.
3. 개시·기각·기각취소·즉시항고 같은 중간 명령도 놓치면 후속 대응이 늦어진다.
4. 조회가 안 되는 사건은 사이트 오류인지 실제 종료인지 한 번에 단정할 수 없다.

AuctionPulse가 경매 기일을 엑셀 동기화 + 변경 메일로 감시하듯, RehabPulse는 **개인회생 인가·명령**을 같은 방식으로 감시한다.

## 2. 목표

| 목표 | 성공 지표 |
|---|---|
| 등록 사건을 나의 사건검색에서 자동 조회 | 1회 실행으로 활성 사건 전체 조회. 사건당 조회(캡차 포함) 완료 |
| 일반내용 핵심 일자 + 진행내용(명령) 스냅샷 저장 | 재실행 시 동일 키 중복 없음, 이전 값과 diff 가능 |
| 변제계획인가결정 발생 시 즉시 알림 | 인가일 공란→값 또는 명령 목록에 `변제계획인가결정` 신규 등장 시 메일 1통 |
| 특이 변경(개시·기각·기각취소·면책·종국·신규 명령) 알림 | 오탐/미탐 0건 (테스트 사건 세트 기준) |
| 조회 예외와 실제 종료를 구분 | 하루 2회(1분 간격) 조회, **3일 연속 결번**일 때만 종료·리스트 제외 |

### 비목표 (Non-goals, v1)

- 인증서(공동인증서) 검색 탭 사용
- 사건 대량 수집·재가공. 등록된 관심 사건만 조회
- 변제계획안 내용 분석, 변제액 계산, 면책 가능성 예측
- 다중 사용자/서버 SaaS. v1은 **개인 로컬 PC 단일 사용자** 도구
- 캡차 우회(토큰 탈취, OCR 농장, 백엔드 API 공격). **화면에 보이는 숫자를 읽어 입력**하는 것만 허용
- 나의 사건검색 외 사설 회생정보 사이트 연동

**사용자**: 개인회생 수임 사건을 추적하는 실무자(본인). Windows PC, Excel, Python, Gmail SMTP(앱 비밀번호). 알림 수신 주소: `kimchangrok.ai@gmail.com` (AuctionPulse와 동일).

### 핵심 시나리오

- **S1. 사건 등록**: 법원명 + `YYYY개회NNNNNN` + 당사자명을 관심 목록에 넣는다.
- **S2. 정기 조회**: 평일 아침 실행하면 활성 사건마다 나의 사건검색을 두 번(1분 간격) 조회하고 엑셀에 반영한다.
- **S3. 인가 알림**: `변제계획인가일`이 생기거나 진행내용(명령)에 `변제계획인가결정`이 뜨면 메일을 보낸다.
- **S4. 특이 변경 알림**: 개시결정, 기각결정, 기각취소결정, 면책, 종국결과, 신규 명령 행이 생기면 메일을 보낸다.
- **S5. 종료 처리**: 조회가 됐는데 `사건이 존재하지 않습니다`가 **하루 두 번 모두**, 그게 **3일 연속**이면 종료로 보고 목록에서 제외한다. 캡차 실패·사이트 오류는 종료가 아니다.

## 4. 기능 요구사항

### FR-1. 사건 등록·관리

- FR-1.1 사용자는 `법원명`, `년도`, `사건구분`(개인회생은 보통 `개회`), `일련번호`, `당사자명`(한글 2자 이상)을 등록·삭제·비활성화할 수 있다.
- FR-1.2 표시용 사건번호는 `YYYY{사건구분}{일련번호}` (예: `2024개회176313`).
- FR-1.3 법원명은 나의 사건검색 드롭다운의 **정식 명칭**만 저장한다 (`서울회생법원`, `인천지방법원`, `수원회생법원`, `의정부지방법원` 등).
- FR-1.4 당사자명은 검색 필수값이다. 로그·메일에는 실명을 쓰되, 사이트 마스킹(`박OO`)과 등록명을 구분해서 보관한다.
- FR-1.5 사건별 `consecutive_miss_days`(기본 0), `활성(Y/N)` 을 유지한다.
- FR-1.6 용어 원칙: 시트명·열 이름·진행구분·명령 명칭은 포털 화면 표기를 그대로 쓴다. 툴이 만드는 판정 열(`인가여부`, `종료여부` 등)만 예외다.

### FR-2. 나의 사건검색 조회

- FR-2.1 **실제 폼 URL**은 iframe이 아니라 이것이다. 바깥 포털 껍데기(`www.scourt.go.kr/portal/information/events/search/search.jsp`)로 자동화하지 않는다.

  `https://ssgo.scourt.go.kr/ssgo/index.on?cortId=www`

- FR-2.2 탭은 **사건번호로 검색**만 사용한다. **인증서로 검색**은 쓰지 않는다.
- FR-2.3 입력 순서 (사건구분은 법원에 따라 목록이 바뀌므로 **법원 먼저**):

  1. 법원 선택 = `{court}` (option value == 한글 라벨)
  2. 년도 선택 = `{year}`
  3. 사건구분 선택 = `{case_type}` (`개회`는 해당 법원에서만 나타남)
  4. 사건일련번호 = `{serial}` (숫자만)
  5. 당사자명 = `{party}` (한글, 빈칸 금지)
  6. 자동입력 방지문자 = 현재 화면의 숫자
  7. 검색

- FR-2.4 캡차: 매 검색 필수. **현재 이미지의 숫자를 읽어 입력**한다. 이전 캡차 문자열을 재사용하지 않는다. 오답이면 새로고침 후 새 이미지를 읽고 1회 재시도.
- FR-2.5 당사자명 빈칸 제출 금지. 데모에서 빈 이름·낡은 캡차로 `사건이 존재하지 않습니다`가 난 적이 있다. 이 거짓 결번을 종료로 치면 안 된다.
- FR-2.6 성공 시에만 결과 탭이 생긴다. 검색 폼에는 `일반내용` / `진행내용`이 없다.
- FR-2.7 요청 간 지연(사건 사이 2~3초 + 지터). 등록 사건만 조회. 다량 저장·재가공 목적의 수집은 하지 않는다.
- FR-2.8 파싱 실패 시 원본 HTML을 `raw/`에 남기고 명확히 실패로 기록한다. 이 실패는 결번(miss)이 아니다.

### FR-3. 확인해야 하는 정보 (조회 성공 후)

데모로 확정한 확인 경로.

#### FR-3.1 일반내용 (기본내용)

아래 칸을 **공란이어도** 저장·비교한다.

| 필드 | 역할 |
|---|---|
| 사건번호, 사건명, 재판부/회생위원, 접수일 | 식별 |
| **개시결정일** | 개시 여부 |
| **변제계획인가일** | ★ 인가 알림 |
| **면책결정일** | 면책 |
| 절차폐지결정일 | 폐지 |
| **종국결과** | 종국 |

#### FR-3.2 진행내용 → 진행구분 = 명령

1. **진행내용** 탭을 연다.
2. **진행구분** 드롭다운을 **명령**으로 바꾼다. `전체`로 읽지 않는다.
3. 필터된 목록의 **법원 행정명령 내용**을 행 단위로 저장한다 (일자, 진행구분/내용, 결과).

반드시 식별할 명령:

| 진행구분 (명령) | 처리 |
|---|---|
| **변제계획인가결정** | ★ 알림 |
| 개인회생절차개시결정 | 특이 변경 |
| 개인회생절차개시신청 기각결정 | 특이 변경 |
| 기각취소결정 | 특이 변경 |

금지명령·보정권고·보정명령·제출명령 등도 스냅샷에는 남긴다. 알림은 위 핵심 명령 + **이전에 없던 명령 행 신규 등장**.

### FR-4. 저장 (엑셀 단일 워크북)

AuctionPulse와 같이 **엑셀 한 파일**이 상태의 단일 저장소다. 기본 `rehabpulse.xlsx`. 별도 DB 없음.

| 시트 | 역할 | 키 |
|---|---|---|
| `사건목록` | 등록 사건, 활성, 인가여부, consecutive_miss_days, 최근 조회 결과 | 법원+사건번호 |
| `일반내용` | 최신 기본내용 일자 | 법원+사건번호 |
| `진행명령` | 진행구분=명령 행 최신본 | 법원+사건번호+일자+내용 |
| `변경이력` | append-only 이벤트 | 실행시각+사건+이벤트 |
| `실행로그` | 실행 시각, 대상 수, 성공/실패/결번 | 실행시각 |
| `종료목록` | 3일 연속 결번으로 뺀 사건 | 법원+사건번호+종료일 |

- FR-4.1 업서트. 사이트에서 사라진 명령 행은 지우지 않고 `삭제됨` 플래그.
- FR-4.2 각 행에 `최초수집일시`, `최종확인일시`, `최종변경일시`, `row_hash`.
- FR-4.3 엑셀 잠금 시 임시 파일 저장 후 안내. 저장 전 `backup/` 사본.
- FR-4.4 첫 수집은 `INITIAL_LOAD`. 알림 제외 (옵션으로 포함 가능).
- FR-4.5 사용자가 추가한 메모 열은 동기화 시 보존.

### FR-5. 변경 탐지와 알림 이벤트

비교 기준은 직전 성공 스냅샷.

| 이벤트 | 조건 | 메일 |
|---|---|---|
| `PLAN_APPROVED` ★ | 변제계획인가일 공란→값, 또는 명령에 `변제계획인가결정` 신규 | 필수 |
| `COMMENCED` | 개시결정일 공란→값, 또는 `개인회생절차개시결정` 신규 | 필수 |
| `DISMISSED` | `개인회생절차개시신청 기각결정` 신규 | 필수 |
| `DISMISSAL_VACATED` | `기각취소결정` 신규 | 필수 |
| `DISCHARGED` | 면책결정일 공란→값 | 필수 |
| `TERMINAL` | 종국결과·절차폐지결정일 공란→값 | 필수 |
| `NEW_ORDER` | 진행명령에 이전 없는 행 | 필수 |
| `ORDER_UPDATED` | 동일 키 행의 내용/결과 변경 | 필수 |
| `CASE_ARCHIVED` | 3일 연속 결번으로 종료 | 필수 |
| `INITIAL_LOAD` | 첫 성공 수집 | 기본 제외 |
| `MISS_DAY` | 그날 두 번 모두 결번 (1일차·2일차) | 메일 없음. 실행로그에만 |

무변경이면 메일 없음 (`send_empty` 기본 false).

### FR-6. 하루 2회 조회와 종료 규칙

조회 예외가 있으므로 결번 한 번으로 종료하지 않는다.

- FR-6.1 실행일마다 사건당 **2회 조회, 간격 60초**. 두 번째가 예외 재시도.
- FR-6.2 캡차 실패·타임아웃·파싱 실패·5xx는 **miss가 아니다**. miss 카운터를 올리지 않고 실행로그에 오류를 남긴다.
- FR-6.3 `사건이 존재하지 않습니다`는, 캡차·입력이 유효한 검색 응답일 때만 not-found.
- FR-6.4 그날 miss로 치는 조건: **두 시도가 모두 not-found**.
- FR-6.5 한 번이라도 사건을 찾으면 `consecutive_miss_days = 0`, 스냅샷 저장, 활성 유지.
- FR-6.6 `consecutive_miss_days`가 **3**이 되면(감시일 기준 3일 연속, 매일 쌍 결번) `CASE_ARCHIVED`. 활성=N, `종료목록`으로 이동, 이후 조회하지 않는다.
- FR-6.7 1~2일 결번은 목록에 남긴다. 종료 메일을 보내지 않는다.

- FR-7.2 설정은 `config/settings.yaml`의 `email`. 비밀번호는 파일에 두지 않고 `REHABPULSE_SMTP_PASSWORD` (없으면 AuctionPulse와 같이 `AUCTIONPULSE_SMTP_PASSWORD` fallback 허용).
- FR-7.3 변경 이벤트 ≥ 1건일 때만 발송. 발송 실패는 실행 실패로 치지 않고 로그에만 남긴다.
- FR-7.4 제목 예:
  - `[RehabPulse] {당사자} 변제계획인가결정`
  - `[RehabPulse] {당사자} 진행 변경`
  - `[RehabPulse] {당사자} 사건 종료(3일 연속 조회 없음)`
- FR-7.5 본문: 법원, 사건번호, 당사자, 이벤트, 일반내용 일자(공란 명시), 신규/변경된 명령 행, 이전 값 vs 새 값. 한글.

## 5. 조회 흐름 (확정)

```
ssgo.scourt.go.kr / 사건번호로 검색
  → 법원 → 년도 → 사건구분(개회) → 일련번호 → 당사자명 → 캡차 → 검색
    → 실패 알림 `사건이 존재하지 않습니다` → not-found (FR-6)
    → 성공
        → 일반내용: 개시결정일 / 변제계획인가일 / 면책결정일 / 종국결과
        → 진행내용 → 진행구분 = 명령 → 법원 행정명령 내용
```

구현 시 주의 (실측):

- WebSquare. 라벨(`법원 선택`, `당사자명 필수입력`)을 id보다 우선.
- 사건구분은 법원 change 이후 다시 읽는다.
- 캡차 이미지는 검색마다 바뀐다. 스크린샷 숫자를 그대로 다음 검색에 쓰지 않는다.
- Google 번역 바가 폼을 가릴 수 있다. 닫고 진행.

## 6. 기술 설계 (Claude Code 구현용)

AuctionPulse 구조를 따른다. 캡차 때문에 **브라우저 자동화가 기본 수집 경로**다.

### 6.1 디렉터리

```
rehabpulse/
  PRD.md                  # 본 문서 (저장소 루트 또는 docs/PRD.md)
  CLAUDE.md               # 구현 에이전트 지침. PRD와 충돌 시 PRD 우선
  rehabpulse/             # 패키지
    __main__.py
    cli.py
    fetch/                # 브라우저 조회 + 파서. 사이트 의존은 여기만
    store/                # 엑셀 업서트
    differ.py
    judge.py              # 인가·종료 판정
    notify/               # SMTP
  config/
    settings.yaml
    rules.yaml            # 명령 명칭, 알림 이벤트 매핑
  tests/
    fixtures/             # 성공 HTML, 결번 알림, 명령 테이블
  scripts/
    register_task.ps1
  backup/
  raw/
  logs/
```

### 6.2 스택

- Python 3.11+, Windows
- Playwright (Chromium)로 ssgo 폼 조작
- 캡차: 캡차 이미지 바이트를 비전 모델(Claude)에 넘겨 6자리 숫자를 받고 입력. 사람 캡차 입력은 v1 폴백(설정 `captcha: manual`)만
- openpyxl, pyyaml
- SMTP 이메일 (AuctionPulse와 동일)

### 6.3 작업 순서 (반드시 이 순서)

1. **M0 조사** — 코드 작성 전에 성공/결번 HTML을 `tests/fixtures/`에 저장하고 `docs/M0_조사메모.md`에 URL·필드·진행구분=명령 DOM을 기록. 시드 사건 박미리 2024개회176313으로 일반내용·명령 테이블 실측.
2. **M1** — fetch + excel_store. 시드 6건 중 조회 가능한 사건을 엑셀에 넣고, 재실행 시 중복 없음.
3. **M2** — differ + judge. `PLAN_APPROVED`, `DISMISSED`, 3일 결번 `CASE_ARCHIVED`를 테스트로 고정.
4. **M3** — CLI, 백업, 로그, 이메일, 작업 스케줄러.

### 6.4 규칙

- 포털 원문 값을 정규화로 잃지 않는다. 판정은 `rules.yaml`.
- SMTP 비밀번호를 코드·yaml에 넣지 않는다.
- 캡차 토큰/쿠키를 훔쳐 검색을 우회하지 않는다.
- 파서 변경 시 fixture 테스트가 통과해야 한다.
